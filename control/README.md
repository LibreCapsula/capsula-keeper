# keeper — управляющая программа (C)

Версия 0.2.0. Собирается чистым C11, зависимости — только libc (termios,
poll, POSIX regex, flock).

```sh
make            # -> build/capsula-keeper
make check      # юнит-тесты парсера фреймов
make fuzz       # фаззер парсера под ASan/UBSan (30k итераций мусора)
sudo make install       # в /usr/local/bin (make uninstall — убрать)
```

Порт ищется автоматически: сканируется `/sys/class/tty` (ttyACM*/ttyUSB*),
выбирается устройство Espressif `303a:1001` (USB-Serial-JTAG). Переопределение:
`--port /dev/ttyACM0` или переменная `KEEPER_PORT`.

**Блокировка порта.** Открытый порт берётся в `flock`: второй процесс
keeper'а получает ошибку «is busy (held by another capsula-keeper process)»
вместо молчаливого перемешивания команд в донгле. Лок отпускается при выходе
(в т.ч. по сигналу).

**`reset --log` не теряет ранние логи.** Порт остаётся открытым от команды
RESET до конца стрима; LOG-кадры, пришедшие, пока ждали ответ «OK reset done»
(самое начало загрузки), буферизуются в устройстве (64 КиБ) и выдаются в
начале лог-стрима, участвуя в `--until`/`--max-lines` наравне с остальными.

**Числовые опции строгие**: `--ms`, `--max-lines`, `--timeout`, тайминги
`loader`/`maskrom` и `baud` проверяются (`bad --ms value` → exit 2), а не
молча превращаются в 0. `log --raw` пишет байты в stdout сразу, не дожидаясь
перевода строки (удобно вместе с `--until`).

**Ресенд при таймауте**: если ответ на команду не пришёл (команда или ответ
потерялись в лог-флуде платы — редкий, но наблюдённый на железе эффект),
`device_command` пересылает команду один раз, прежде чем выдать timeout.
Все команды протокола идемпотентны, так что повтор безопасен. Плюс к этому
ping/status/release/baud дополнительно ретраятся на уровне CLI.

Файлы: `src/proto.c` — парсер фреймов с ресинхронизацией, `src/tty.c` — поиск,
raw-открытие порта и flock (DTR/RTS сбрасываются, чтобы некоторые платы ESP32
не уходили в ресет при открытии), `src/device.c` — команды, лог-стрим и буфер
ранних логов, `src/main.c` — CLI, `src/usb.c` — детект Rockchip download-режимов.
Тесты: `tests/proto_test.c` (юнит-тесты парсера, `make check`),
`tests/fuzz_proto.c` (фаззер, `make fuzz`).
Без железа: `python3 ../e2e_test.py` (мок-донгл на pty) и
`python3 ../stress_test.py` (враждебный мок: обрывы соединения, мусор на
проводе, rapid-fire, лок порта, burst 500 строк, ранние логи `reset --log`).
