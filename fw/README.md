# keeper-fw

Прошивка донгла для ESP32-S3 (проверено на сборке для ESP32-S3 SuperMini,
модуль N8R2 — 8 МБ flash; для N16R8 менять нечего, размер не критичен).

## Компоненты

- `main/bridge.c` — мост: UART1 (пины 4/5, 1500000 8N1) ↔ USB-Serial-JTAG.
  Задача `logfwd` стримит логи платы в хост фреймами LOG; задача `cmd`
  разбирает команды `@...` и пересылает остальное в плату.

  Приоритеты: `cmd` (6) выше `logfwd` (5) — когда плата заваливает UART
  логами, команды и ответы должны проходить всегда. LOG-записи best-effort:
  `send_log` ждёт места в USJ TX-буфере ≤ 20 мс и иначе считает чанк
  потерянным (`drops`), а `send_ctrl` наоборот ждёт до 2 с — ответ на команду
  не теряется в потоке логов. До этого фикса первая после простоя команда
  иногда выпадала по таймауту: TX-буфер был забит лог-флудом, `logfwd`
  заедал `cmd`, и ответ не успевал за 200 мс.
- `main/buttons.c` — три независимых канала. Reset/Recovery — GPIO 6/7 в
  режиме **output open-drain** (в покое линия отпущена, «нажатие» —
  притянуть к земле; push-pull и подтяжки к питанию не используются, чтобы
  не лезть 3.3 В в 1.8-вольтовые домены и на вход SARADC). MaskROM — GPIO 8,
  push-pull на затвор внешнего nMOS, замыкающего FLASH_D0 платы на GND
  (обвязка обязательна: ~330 Ом в цепь затвора и 10 кОм затвор→GND против
  паразитного заряда, пока пин донгла висит); логика инвертирована
  относительно кнопок: `press` = открыть транзистор. Отдельная задача
  исполняет последовательности: одиночное нажатие с таймаутом, `LOADER`
  (recovery → reset → отпускания с паузами) и `MASKROM` (замыкание →
  reset → снятие).
- `main/pins.h` — назначения пинов, менять под свою разводку здесь.

## Сборка

```sh
./setup.sh        # один раз: ESP-IDF v5.5 -> ../.esp-idf, тулчейн -> ../.idf-tools
./build.sh build  # или flash / monitor / menuconfig
```

Точка входа `idf.py`; окружение подхватывается автоматически из `../.esp-idf`.

## Отладка прошивки

Логи самой прошивки (ESP_LOG) идут в UART0 (пины TX/RX SuperMini, 115200) и
**не** попадают в USB-канал данных, так что поток для хоста остаётся чистым
фреймовым протоколом. В `sdkconfig.defaults` можно включить
`CONFIG_ESP_CONSOLE_NONE=y`, если UART0 нужен для чего-то ещё.
