# Протокол capsula-keeper (ПК ↔ донгл)

Транспорт: USB CDC через периферию USB-Serial-JTAG ESP32-S3
(`VID:PID 303a:1001`), на хосте это `/dev/ttyACM*`. Порт открывается в raw-режиме
с снятыми DTR/RTS (чтобы донгл не рестартовал при открытии). Скорость USB-канала
роли не играет; скорость UART целевой платы задаётся отдельно (`@BAUD`, по
умолчанию 1500000 8N1 — стандартный debug UART Rockchip).

## ПК → донгл: сырой поток + «@»-команды

Всё, что присылает хост, уходит в UART целевой платы, **кроме** строк,
начинающихся с `@` — они перехватываются как команды донглу:

- строка команды накапливается до `\n` / `\r` (лимит буфера 96 байт: при
  переполнении команда выполняется с усечённой строкой);
- `@@` в начале строки — литеральный `@` в консоль платы;
- имя команды нечувствительно к регистру, аргументы разделяются
  пробелами/табуляциями.

### Команды

| Команда | Аргументы | Ответ | Действие |
|---|---|---|---|
| `@PING` | — | `OK pong` | проверка связи |
| `@VER` | — | `OK keeper-fw <ver>` | версия прошивки донгла |
| `@STAT` | — | `OK up_s=… baud=… drops=… rx_total=… rst=… rec=… msk=…` | аптайм, скорость, потери, состояния кнопок |
| `@BAUD <n>` | 1200…5000000 | `OK baud=<n>` | сменить скорость UART платы |
| `@RESET [ms]` | умолчание 1000 | `OK reset done` | импульс Reset: press → ms → release |
| `@PRESS <btn> [ms]` | без ms — до `@RELEASE` | `OK pressed` / `OK press done` | «нажать» кнопку |
| `@RELEASE <btn>` | — | `OK released` | «отпустить» кнопку |
| `@LOADER [pre rst post]` | умолч. 200/1000/3000 | `OK loader done` | последовательность Recovery+Reset (см. ниже) |
| `@MASKROM [pre rst post]` | умолч. 100/1000/1500 | `OK maskrom done` | принудительный MaskROM через FLASH_D0 (см. ниже) |

Имена кнопок: `reset`/`rst`, `recovery`/`rec`, `maskrom`/`tp48`/`flash_d0`.

Ошибки: `ERR busy` (предыдущая последовательность ещё выполняется),
`ERR unknown command: …`, `ERR unknown button (reset|recovery|maskrom)`,
`ERR baud out of range`, `ERR empty command`.

### Последовательности

Кнопки Reset/Recovery — открытый сток: «нажатие» = притянуть линию платы к
GND, «отпускание» = отпустить (донгл никогда не подаёт напряжение на плату).
Кнопка MaskROM — наоборот, push-pull на затвор внешнего N-MOSFET, который
замыкает FLASH_D0 на GND (подробности и схему см. `wiring.md`).

- `@LOADER`: press Recovery → `pre` → press Reset → `rst` → release Reset →
  `post` → release Recovery. Плата стартует с зажатым Recovery — BootROM
  должен войти в LOADER-режим (требует поддержки клавиши в U-Boot, см.
  `wiring.md`).
- `@MASKROM`: press MaskROM → `pre` → press Reset → `rst` → release Reset →
  `post` → release MaskROM. BootROM не может прочитать загрузчик из NAND
  (FLASH_D0 замкнут) и гарантированно входит в MaskROM.

Последовательность исполняется отдельной задачей; ответ `OK … done` приходит
по её завершении. Пока она идёт, новые последовательности получают `ERR busy`
(одиночный `@PRESS`/`@RELEASE` при этом работает).

## Донгл → ПК: бинарные фреймы

```
[SOF 0x5A][type u8][len u16 LE][payload, до 4096 байт]
```

| type | Имя | Payload |
|---|---|---|
| `0x01` | LOG | сырые байты из UART целевой платы |
| `0x02` | CTRL | ASCII-строка — ответ на команду (`OK …` / `ERR …`) |

Особенности:

- **Ресинхронизация.** Парсер хоста (`control/src/proto.c`) выбрасывает мусор
  между фреймами и ищет следующий валидный `0x5A` — поток логов, в котором
  встретился байт `0x5A`, не ломает канал.
- **LOG — best-effort.** При флуде логами платы чанки LOG теряются и
  учитываются в `drops` (в `@STAT`); ответ CTRL ждёт места в буфере до 2 с и
  не теряется. Хост при таймауте пересылает команду один раз — команды
  идемпотентны.
- **Ранние логи `reset --log`.** LOG-фреймы, пришедшие, пока CLI ждал ответ
  на `@RESET` (самое начало загрузки платы), буферизуются на хосте (64 КиБ) и
  выдаются первыми в стриме.
